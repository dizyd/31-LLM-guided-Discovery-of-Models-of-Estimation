2.2 The five things that will actually trip you up

2.2.1 Indentation is syntax, not style

In R, braces delimit blocks and whitespace is decorative. In Python, indentation is the only block delimiter. This is a syntax error:

def f(x):
return x + 1        # not indented -> IndentationError

Consistency matters: the whole file uses four spaces. Never mix tabs and spaces.

2.2.2 numpy arrays are R’s vectors and matrices, but stricter about shape

An R vector has length(). A numpy array has a shape — a tuple of dimension sizes.

import numpy as np

a = np.array([1.0, 2.0, 3.0])
a.shape          # (3,)      one-dimensional, 3 elements
b = np.zeros((4, 3))
b.shape          # (4, 3)    4 rows, 3 columns

(3,) with the trailing comma is a one-element tuple — Python’s way of distinguishing (3,) (a tuple) from (3) (just the number 3 in brackets). A shape of (3,) is not the same as (3, 1) or (1, 3), and functions will complain about the difference.

axis= is R’s MARGIN in apply(), but axis names the dimension that disappears:

m = np.array([[1., 2., 3.],
              [4., 5., 6.]])          # shape (2, 3)

m.sum(axis=0)    # array([5., 7., 9.])     collapses rows    -> shape (3,)
m.sum(axis=1)    # array([ 6., 15.])       collapses columns -> shape (2,)

In R, apply(m, 1, sum) sums over rows keeping one value per row; m.sum(axis=1) is the same thing. The mnemonic that works: axis is the index that gets eaten.

2.2.3 Broadcasting is R’s recycling, but by shape

R recycles a short vector to match a long one. Numpy aligns shapes from the right and stretches any dimension of size 1. This is used constantly in this codebase:

cues    = np.zeros((68, 10))     # 68 test items, 10 cue dimensions
ex_cues = np.zeros((12, 10))     # 12 exemplars,  10 cue dimensions

# We want all 68 x 12 differences. Insert a length-1 axis in each:
cues[:, None, :]        # shape (68,  1, 10)
ex_cues[None, :, :]     # shape ( 1, 12, 10)

diff = cues[:, None, :] - ex_cues[None, :, :]
diff.shape              # (68, 12, 10)

None inside an index means “insert a new axis of length 1 here” (np.newaxis is a more readable synonym for the same thing). : means “all of this axis”, exactly like R’s empty index in m[, 1].

Numpy then stretches the size-1 axes: diff[i, j, d] is cues[i, d] - ex_cues[j, d]. This is how the GCM computes every probe–exemplar distance without a single loop. In R you would write nested for loops or outer(); here it is one line and roughly 100× faster.

2.2.4 (n_items, n_subs) vs (n_subs, n_items) — the trap that bit me

Boolean masking flattens in row-major order (last axis varies fastest). So if two arrays hold the same data but transposed, masking them with “the same” mask silently pairs the wrong elements.

estimates   = ...      # shape (68, 48)   items x participants
centaur_nll = ...      # shape (48, 68)   participants x items
valid       = ...      # shape (68, 48)

estimates[valid]            # flattens item-major:        item0-sub0, item0-sub1, ...
centaur_nll[valid.T]        # flattens participant-major: sub0-item0, sub0-item1, ...

Both give a 1-D array of the same length, so nothing errors — the numbers are just paired with the wrong partner. I made exactly this mistake while writing response_style_summary(); it reported that round numbers were no easier for Centaur (4.08 vs 3.95 nats) when the truth is 2.98 vs 5.03.

WarningThe rule this codebase follows

Anything to do with Centaur is in (n_subs, n_items) order. Anything read from the behavioural CSV is in (n_items, n_subs) order. Transpose explicitly at the boundary and never mask across the two layouts. When in doubt, print(x.shape).

2.2.5 Mutable default arguments

def bad(items=[]):        # DANGER: the list is created ONCE, at definition time
    items.append(1)
    return items

Calling bad() twice returns [1] then [1, 1]. The convention — used throughout this codebase — is None as the default plus a fill-in on the first line:

def good(items=None):
    items = [] if items is None else items

You will see this pattern constantly, e.g. rng = np.random.default_rng() if rng is None else rng.

2.3 Smaller things you will see

Dataclasses are R’s setClass without the ceremony — a record type with named fields:

3 What the pipeline does, and why v1 failed

3.1 The ASMR idea

Following Binz et al. (2025):

  1. Fit an interpretable cognitive model (GCM, CAM, …) to each participant by maximum likelihood, getting a negative log-likelihood (NLL) per trial.
  2. Take Centaur’s cached per-trial NLL for the same data.
  3. Compute \(\Delta = \text{NLL}_{\text{model}} - \text{NLL}_{\text{Centaur}}\) per trial. Trials with large \(\Delta\) are ones Centaur predicts well but the cognitive model does not — points that are in principle predictable but not yet explained.
  4. Send those trials, plus the model’s source code, to a reasoning LLM (Qwen3-32B) and ask for a better model.
  5. Repeat.

3.2 Four reasons v1 did not work

3.2.1 Two alignment bugs

Participants were indexed by ID_n (alphabetical rank of the Prolific ID) on the Centaur side but by CSV column order on the behavioural side. For Mammals, ID_n 0 is 0xhc0yxm5czl while CSV column 0 is chp46vl70814. Same 48 people, different order — so \(\Delta\) compared one person’s model fit against a different person’s Centaur fit.

Separately, the NLL arrays are sorted by item ID, but the narrative text lists trials in presentation order. Reading the n-th <<...>> from the text to label the n-th trial therefore quoted the wrong item and the wrong estimate.

3.2.2 Incommensurable likelihoods

Centaur’s NLL is \(-\log P(\text{token})\) — a probability mass. The cognitive model’s was \(-\log f(y)\) — a probability density. Because people report round numbers, a density is structurally penalised:

Mammals test phase
estimates that are multiples of 10 80.9%
multiples of 100 47.5%
distinct values per participant (of 68 trials) 36.5
responses repeating a value that person already gave 46.3%
Centaur mean NLL
response is a multiple of 100 2.98
not a multiple of 100 5.03
value the participant reused 3.08
value used only once 5.85
correlation with actual estimation error r = .12

Centaur sits at 4.06 nats/trial, the density-based GCM at 7.63. A response-style-only null — resample the person’s own estimates, ignoring the item entirely — gets 3.30.

ImportantThe consequence for SRM

\(\Delta\) is largest exactly where Centaur’s NLL is smallest: on round and repeated responses. So thresholding \(\Delta\) selected trials by how the participant wrote the number down, not by model misfit. With threshold = 5, 1418 of 3264 trials were flagged, which also overflowed the context window.

3.2.3 Crashed models became numbers

nll_truncnorm_woS returned 1e12 per trial whenever the model raised. So srm_model_1p_0_iteration_4.npz holds nll.sum() = 6.8e13 = 68 trials × 1e12. That model crashed; no exception reached the try block, the rollback was commented out, and the sentinel was reported as an exploded AIC.

3.2.4 An unusable prompt

The LLM saw item names (Item: Zebra) although the model only ever sees ten anonymous MDS coordinates — there is no way to connect the two. It never saw the model’s prediction or the true value. And the fit ran on z-standardised data while the prompt quoted raw days, so any constant the LLM wrote was off by orders of magnitude.

Line by line:

4.2.5 The guard: assert_alignment

def assert_alignment(ds, nd=None):
    nd = _narrative(ds.domain) if nd is None else nd
    rank = {int(i): k for k, i in enumerate(ds.item_ids)}

    for p, row in nd.iterrows():
        assert row["ID"] == ds.participant_ids[p]
        order = [int(x) for x in str(row["ID_items"]).split(",")][-ds.n_items:]
        said  = re.findall(r"<<(.*?)>>", row["text"])[-ds.n_items:]

This independently re-derives the estimates from the narrative text Centaur actually read, then compares them to the behavioural file. If either ordering drifts, the numbers disagree and the load fails.

re.findall(r"<<(.*?)>>", ...) is a regular expression. The r"..." prefix is a raw string (backslashes stay literal — R’s equivalent of doubling them). (.*?) is a non-greedy capture group: without the ? it would match from the first << to the last >>, swallowing the whole transcript.

        from_text = np.empty(ds.n_items, dtype=float)
        for iid, val in zip(order, said):
            from_text[rank[iid]] = float(val)

zip pairs the two lists elementwise (R’s Map). Each response is written to the slot for its item ID, converting presentation order into item-ID order. This is the fix for bug 2 in miniature.

5 asmr_likelihood.py — the reporting layer

251 lines. This is the scientifically important module.

5.1 The idea

A person who believes a zebra matures in about 900 days does not say “900”. They say “900”, or “1000”, or “2 years”. The cognitive model predicts a latent quantity; the person reports it on a coarse grid. Modelling only the first half and comparing against a model that captures both is not a fair comparison.

So we add a reporting stage. With granularities \(g \in \{1, 5, 10, 50, 100, 500, 1000\}\) and mixing weights \(\pi_g\):

\[ P(y) = \sum_g \pi_g \cdot \mathbb{1}[y \equiv 0 \bmod g] \cdot P_g(y), \qquad P_g(y) = \frac{\Phi\!\left(\frac{y + g/2 - \mu}{\sigma}\right) - \Phi\!\left(\frac{y - g/2 - \mu}{\sigma}\right)}{Z_g} \]

Read it as: with probability \(\pi_g\) the person reports to the nearest multiple of \(g\); given that, the chance they land on \(y\) is the latent distribution’s mass in the bin around \(y\).

Grid-\(g\) bins tile \([-g/2,\; N_g g + g/2]\) exactly, so \(Z_g\) is closed form and each \(P_g\) sums to one over its own support. With \(\sum_g \pi_g = 1\) the mixture is a proper PMF — directly comparable to Centaur’s token probability.

TipWhy \(\pi_g\) is free

It is estimated from each participant’s training-phase responses, so it costs no free parameters in the test-phase fit. A person’s rounding habit is measured before the data we are modelling.

5.2 fit_granularity_weights(train_responses, grids=GRIDS, alpha=1.0)

def coarsest_grid(y, grids=GRIDS, tol=1e-8):
    y = np.asarray(y, dtype=float)
    out = np.zeros(y.shape, dtype=int)
    for k, g in enumerate(grids):
        on = np.abs(y / g - np.round(y / g)) < tol
        out = np.where(on, k, out)
    return out

y / g - round(y / g) is zero exactly when y is a multiple of g; comparing to a small tolerance rather than == 0 avoids floating-point trouble. Because grids is ordered coarsest-last and each iteration overwrites, out ends up holding the coarsest grid each value lies on. np.where(cond, a, b) is R’s ifelse(), elementwise.

def fit_granularity_weights(train_responses, grids=GRIDS, alpha=1.0):
    y = np.asarray(train_responses, dtype=float)
    y = y[np.isfinite(y)]
    counts = np.full(len(grids), float(alpha))
    if y.size:
        idx = coarsest_grid(y, grids)
        counts += np.bincount(idx, minlength=len(grids))
    return counts / counts.sum()

np.bincount tabulates counts of each integer — R’s tabulate(). minlength guarantees all seven slots exist even if some grid never occurs. Starting counts at alpha = 1 is Laplace smoothing: no grid ever gets probability zero, which matters because a zero would make any test response on that grid infinitely surprising.

5.3 _log_ndtr_diff(a, b) — numerically stable \(\log(\Phi(b) - \Phi(a))\)

Computing \(\Phi(b) - \Phi(a)\) naively then taking the log underflows to \(-\infty\) in the tails — and the optimiser spends a lot of time in the tails.

def _log_ndtr_diff(a, b):
    a, b = np.asarray(a, dtype=float), np.asarray(b, dtype=float)
    lo, hi = np.minimum(a, b), np.maximum(a, b)

    use_upper = (lo + hi) > 0.0
    x_big  = np.where(use_upper, -lo, hi)
    x_smll = np.where(use_upper, -hi, lo)

    log_big  = log_ndtr(x_big)
    log_smll = log_ndtr(x_smll)
    ratio    = np.clip(log_smll - log_big, None, -1e-12)
    return log_big + np.log1p(-np.exp(ratio))

log_ndtr from scipy.special computes \(\log \Phi(x)\) accurately even at \(x = -40\).

The algebra: factor out the larger term, \[\log(\Phi(b) - \Phi(a)) = \log \Phi(b) + \log\!\left(1 - \tfrac{\Phi(a)}{\Phi(b)}\right)\] and compute the ratio in log space. np.log1p(x) is \(\log(1+x)\), accurate for tiny x.

The use_upper switch handles the right tail. When both bounds are far positive, \(\Phi(a)\) and \(\Phi(b)\) are both ≈ 1 and their ratio ≈ 1, so log1p(-1) → \(-\infty\) catastrophically. By symmetry \(\Phi(b) - \Phi(a) = \Phi(-a) - \Phi(-b)\), so we flip signs and work in the left tail where log_ndtr is accurate. (lo + hi) > 0 tests the midpoint.

np.clip(x, None, -1e-12) caps the ratio just below zero (None = no lower bound), guarding against log1p(0) when rounding makes the two identical.

5.4 grid_masks(y, ...) — precompute what the optimiser would recompute

def grid_masks(y, grids=GRIDS, tol=1e-8):
    y = np.asarray(y, dtype=float)
    m = np.stack([np.abs(y / g - np.round(y / g)) < tol for g in grids])
    m[0] |= ~m.any(axis=0)
    return m

Which responses lie on which grid depends only on the data, never on the parameters. So it is computed once per participant and reused across every objective evaluation — worth roughly a 2× speedup, because the optimiser calls the likelihood thousands of times.

m[0] |= ~m.any(axis=0) is a safety net: |= is in-place OR, so any response on no grid (a non-integer estimate) is forced onto the finest grid. Without it such a response would have zero support and produce NaN.

5.5 logpmf_reported(...) — the PMF itself

    g   = np.asarray(grids, dtype=float)[:, None]        # (G, 1)
    loc = loc[None, :]                                   # (1, n)

    half = g / 2.0
    log_bin = _log_ndtr_diff(
        (edge(np.maximum(y[None, :] - half, lo_support)) - loc) / sigma,
        (edge(y[None, :] + half) - loc) / sigma,
    )
    log_z = _log_ndtr_diff(
        (edge(np.maximum(-half, lo_support)) - loc) / sigma,
        (edge(np.floor(ub / g) * g + half) - loc) / sigma,
    )

    comps = np.where(masks, log_pi[:, None] + log_bin - log_z, -np.inf)

    top = comps.max(axis=0)
    return top + np.log(np.exp(comps - top[None, :]).sum(axis=0))

This is broadcasting doing real work. g is (7, 1), loc is (1, n), so g - loc broadcasts to (7, n) — every grid against every trial, in one array. Both _log_ndtr_diff calls therefore happen once rather than once per grid.

NoteWhy that matters

The original loop-over-grids version made 14 small calls per objective evaluation. At 1744 evaluations per participant fit, the per-call Python overhead dominated. Vectorising took a single-participant fit from 3.0 s to 1.4 s with identical results.

  • edge is a lambda (an anonymous function, R’s \(x)) that is the identity for dist="normal" and np.log for dist="lognormal". Defining it once keeps the two distributions on one code path.
  • np.floor(ub / g) * g is the largest multiple of g at or below the ceiling — the top of grid g’s support.
  • np.where(masks, ..., -np.inf) zeroes out (in log space) every grid a response does not lie on.
  • The last two lines are logsumexp written out: subtract the max, exponentiate, sum, take the log, add the max back. Doing it inline rather than calling scipy.special.logsumexp removed measurable overhead.

def nll_reported(theta, model_fn, y, cues, ex_cues, ex_crit, pi, ub,
                 sigma_scale=1.0, dist="normal", agg="sum", mask=None, masks=None):
    theta = np.asarray(theta, dtype=float)
    sigma = float(sigma_scale) * float(softplus(theta[-1])) + SIGMA_MIN
    pred  = predict(model_fn, theta[:-1], cues, ex_cues, ex_crit)

theta[:-1] is everything but the last element; theta[-1] is the last (negative indexing counts from the end). The last parameter is the hidden noise parameter the LLM never sees.

softplus(x) = log(1 + exp(x)) maps any real to a positive number smoothly. Multiplying by sigma_scale — set to that participant’s response SD — means theta[-1] ≈ 0 already gives a sensible sigma, keeping BFGS well conditioned. v1 started sigma at 0.01, which on the raw scale is an absurdly sharp distribution and a terrible starting point.

6.1 The contract

6.2 The GCM, annotated

6.3 The other seeds

  • CAM (11 parameters) — linear. intercept = mean(ex_crit) + parameters[0] * std(ex_crit), weights scaled by std(ex_crit) / std(ex_cues) so all parameters are order 1.
  • RulEx-J (22) — alpha * CAM + (1 - alpha) * GCM, with alpha through a sigmoid. Manuscript Eq. 5.
  • MAPP (3) — the Mapping model. Cues are recoded to correlate positively with the criterion, averaged to a single value, then mapped to a typical criterion value. Implemented as a kernel (Nadaraya–Watson) regression: the bin width becomes a bandwidth. This keeps it differentiable for gradient-based fitting, at the cost of soft rather than hard bins.
  • Constant (1) — same prediction on every trial. Uses no information about the item, so under the shared reporting layer it is the honest “response style only” null. Whatever a real model gains over this is what knowing the item buys.

Fitting is the slow part: BFGS with numerical gradients needs k+1 extra evaluations per gradient step (there is no analytic gradient for arbitrary LLM-written code). The 48 per-participant fits are independent, so they parallelise perfectly.

NoteWhy workers get source, not the function

Model functions come from exec, and exec-created functions cannot be pickled — Python’s multiprocessing serialises arguments to send them between processes, and it has no way to reconstruct a function with no importable module. So each worker receives the source text and rebuilds the function once, in its own _worker_init. _WORKER is a module-level dict acting as per-process storage.

def format_covariates(ds):

def residualize(delta, ds):
    cov = format_covariates(ds)
    out = np.full_like(delta, np.nan)
    for p in range(delta.shape[0]):
        m = np.isfinite(delta[p])
        if m.sum() <= cov.shape[-1]:
            out[p, m] = delta[p, m]
            continue
        X, d = cov[p][m], delta[p][m]
        beta, *_ = np.linalg.lstsq(X, d, rcond=None)
        out[p, m] = d - X @ beta
    return out

11 asmr_evaluate.py — individual differences without overfitting

253 lines.

11.1 The design

You raised the right concern: fitting one shared model form to everyone may hide real strategy differences. But discovering a bespoke model per person overfits badly — with 68 trials the LLM will happily tailor a model to one person’s quirks.

The resolution is model selection over a library:

  1. Run ASMR several times with different seeds and starting models.
  2. Every validated model along the way goes into library.jsonl.
  3. Score every library member against every participant on held-out items.
  4. Assign each participant their best-scoring member.

Individual differences then show up as which model wins for whom — the same logic as your manuscript’s posterior model probabilities, and directly comparable to Table 2.

11.2 per_participant_heldout(...) and evaluate_library(...)

seed fixes the folds and is identical for every library member, so the comparison is paired — the same items are held out for every model.

13.2 A new seed model

Write it as a string following the contract, add it to SEED_MODELS, and validate:

MODEL_MINE = PREAMBLE + '''
NUM_PARAMETERS = 2

def model(parameters, cues, ex_cues=None, ex_crit=None):
    """Compute predicted criterion estimate."""
    mu    = np.mean(ex_crit)
    scale = np.std(ex_crit)
    d     = np.linalg.norm(cues[:, None, :] - ex_cues[None, :, :], axis=-1)
    near  = d.min(axis=1)
    return mu + parameters[0] * scale + parameters[1] * scale * near
'''

SEED_MODELS["Nearest"] = MODEL_MINE
from asmr_codegen import validate_model_code
rep = validate_model_code(MODEL_MINE, ds.cues, ds.ex_cues, ds.ex_crit)
print(rep.ok, rep.num_parameters, rep.error)

Always validate before running — it catches the shape, dead-parameter and finiteness mistakes in seconds.

13.3 The response-perseveration extension

The largest remaining gap. Centaur is autoregressive over the participant’s own answer history, so it exploits the fact that 46% of test responses repeat a value that person already gave. A cognitive model predicting one quantity per item structurally cannot.

Residual evidence: after residualising, corr(\(\Delta\), reused) is driven to 0 by construction, but before residualising it is +0.21 — that is real, unmodelled structure.

ds.pres_pos preserves the presentation order needed to build this. A model would need access to the responses given before the current trial, which means extending the model contract beyond (parameters, cues, ex_cues, ex_crit). That is a deliberate scope increase, not a small edit — but it is the obvious next scientific step, and arguably a finding in its own right.

13.4 A different response distribution

logpmf_reported already switches on dist. Adding a third would mean defining loc, edge and lo_support for it in that function. The _check_pmf_sums_to_one self-test should be run for any new one.

## The five things that will actually trip you up

### Indentation is syntax, not style

In R, braces delimit blocks and whitespace is decorative. In Python, **indentation is the
only block delimiter**. This is a syntax error:

```python
def f(x):
return x + 1        # not indented -> IndentationError
```

Consistency matters: the whole file uses four spaces. Never mix tabs and spaces.

### `numpy` arrays are R's vectors and matrices, but stricter about shape

An R vector has `length()`. A numpy array has a `shape` — a *tuple* of dimension sizes.

```python
import numpy as np

a = np.array([1.0, 2.0, 3.0])
a.shape          # (3,)      one-dimensional, 3 elements
b = np.zeros((4, 3))
b.shape          # (4, 3)    4 rows, 3 columns
```

`(3,)` with the trailing comma is a one-element tuple — Python's way of distinguishing
`(3,)` (a tuple) from `(3)` (just the number 3 in brackets). A shape of `(3,)` is *not*
the same as `(3, 1)` or `(1, 3)`, and functions will complain about the difference.

`axis=` is R's `MARGIN` in `apply()`, but **`axis` names the dimension that disappears**:

```python
m = np.array([[1., 2., 3.],
              [4., 5., 6.]])          # shape (2, 3)

m.sum(axis=0)    # array([5., 7., 9.])     collapses rows    -> shape (3,)
m.sum(axis=1)    # array([ 6., 15.])       collapses columns -> shape (2,)
```

In R, `apply(m, 1, sum)` sums *over* rows keeping one value per row; `m.sum(axis=1)` is
the same thing. The mnemonic that works: *`axis` is the index that gets eaten*.

### Broadcasting is R's recycling, but by shape

R recycles a short vector to match a long one. Numpy aligns shapes from the **right** and
stretches any dimension of size 1. This is used constantly in this codebase:

```python
cues    = np.zeros((68, 10))     # 68 test items, 10 cue dimensions
ex_cues = np.zeros((12, 10))     # 12 exemplars,  10 cue dimensions

# We want all 68 x 12 differences. Insert a length-1 axis in each:
cues[:, None, :]        # shape (68,  1, 10)
ex_cues[None, :, :]     # shape ( 1, 12, 10)

diff = cues[:, None, :] - ex_cues[None, :, :]
diff.shape              # (68, 12, 10)
```

`None` inside an index means "insert a new axis of length 1 here" (`np.newaxis` is a more
readable synonym for the same thing). `:` means "all of this axis", exactly like R's empty
index in `m[, 1]`.

Numpy then stretches the size-1 axes: `diff[i, j, d]` is `cues[i, d] - ex_cues[j, d]`.
This is how the GCM computes every probe–exemplar distance without a single loop. In R you
would write nested `for` loops or `outer()`; here it is one line and roughly 100× faster.

### `(n_items, n_subs)` vs `(n_subs, n_items)` — the trap that bit me

Boolean masking flattens in **row-major** order (last axis varies fastest). So if two
arrays hold the same data but transposed, masking them with "the same" mask silently pairs
the wrong elements.

```python
estimates   = ...      # shape (68, 48)   items x participants
centaur_nll = ...      # shape (48, 68)   participants x items
valid       = ...      # shape (68, 48)

estimates[valid]            # flattens item-major:        item0-sub0, item0-sub1, ...
centaur_nll[valid.T]        # flattens participant-major: sub0-item0, sub0-item1, ...
```

Both give a 1-D array of the same length, so **nothing errors** — the numbers are just
paired with the wrong partner. I made exactly this mistake while writing
`response_style_summary()`; it reported that round numbers were no easier for Centaur
(4.08 vs 3.95 nats) when the truth is 2.98 vs 5.03.

::: {.callout-warning}
## The rule this codebase follows
Anything to do with Centaur is in **`(n_subs, n_items)`** order. Anything read from the
behavioural CSV is in **`(n_items, n_subs)`** order. Transpose explicitly at the boundary
and never mask across the two layouts. When in doubt, `print(x.shape)`.
:::

```python
def bad(items=[]):        # DANGER: the list is created ONCE, at definition time
    items.append(1)

```

Calling `bad()` twice returns `[1]` then `[1, 1]`. The convention — used throughout this

```python
def good(items=None):
    items = [] if items is None else items
```

You will see this pattern constantly, e.g. `rng = np.random.default_rng() if rng is None

## Smaller things you will see

**Dataclasses** are R's `setClass` without the ceremony — a record type with named fields:

```python
from dataclasses import dataclass

@dataclass
class Fit:
    theta: np.ndarray
    k:     int
    ok:    np.ndarray = None      # a default
```

`@dataclass` is a *decorator*: a function that takes the class and returns a modified one.
It writes the constructor for you, so `Fit(theta=..., k=11, ok=...)` just works, and you
read fields with `fit.theta`. The `: np.ndarray` are *type hints* — documentation only,
Python does not enforce them.

**Properties** are fields computed on access:

```python
    @property
    def aic(self):
        return 2.0 * self.k * int(self.ok.sum()) + 2.0 * self.total_nll
```

You write `fit.aic`, not `fit.aic()`. `self` is the object itself — R's `.self` in R5
classes, and it must be the first argument of every method.

**Leading underscore** means private-by-convention: `_narrative()` is an internal helper,
not part of the module's public interface. Python does not enforce it.

**`if __name__ == "__main__":`** at the bottom of a file guards code that should run when
the file is executed directly (`python asmr_data.py`) but *not* when it is imported. Every
module here uses it for a self-test. It is R's
`if (sys.nframe() == 0)`, and it matters here because it makes each module independently
runnable as a diagnostic.

```python
f"{x:.3f}"       # 3 decimal places
```

# What the pipeline does, and why v1 failed {#sec-problem}

## The ASMR idea

Following Binz et al. (2025):

1. Fit an interpretable cognitive model (GCM, CAM, …) to each participant by maximum
   likelihood, getting a **negative log-likelihood (NLL) per trial**.
2. Take Centaur's cached per-trial NLL for the same data.
3. Compute $\Delta = \text{NLL}_{\text{model}} - \text{NLL}_{\text{Centaur}}$ per trial.
   Trials with large $\Delta$ are ones Centaur predicts well but the cognitive model does
   not — points that are *in principle predictable* but *not yet explained*.
4. Send those trials, plus the model's source code, to a reasoning LLM (Qwen3-32B) and ask
   for a better model.
5. Repeat.

## Four reasons v1 did not work

### Two alignment bugs

Participants were indexed by `ID_n` (alphabetical rank of the Prolific ID) on the Centaur
side but by **CSV column order** on the behavioural side. For Mammals, `ID_n` 0 is
`0xhc0yxm5czl` while CSV column 0 is `chp46vl70814`. Same 48 people, different order — so
$\Delta$ compared one person's model fit against a *different* person's Centaur fit.

Separately, the NLL arrays are sorted by **item ID**, but the narrative text lists trials in
**presentation order**. Reading the *n*-th `<<...>>` from the text to label the *n*-th
trial therefore quoted the wrong item and the wrong estimate.

### Incommensurable likelihoods

Centaur's NLL is $-\log P(\text{token})$ — a probability **mass**. The cognitive model's
was $-\log f(y)$ — a probability **density**. Because people report round numbers, a
density is structurally penalised:

| Mammals test phase | |
|---|---|
| estimates that are multiples of 10 | 80.9% |
| multiples of 100 | 47.5% |
| distinct values per participant (of 68 trials) | 36.5 |
| responses repeating a value that person already gave | 46.3% |

| Centaur mean NLL | |
|---|---|
| response is a multiple of 100 | **2.98** |
| not a multiple of 100 | **5.03** |
| value the participant reused | **3.08** |
| value used only once | **5.85** |
| correlation with actual estimation error | **r = .12** |

# `asmr_likelihood.py` — the reporting layer {#sec-likelihood}

251 lines. This is the scientifically important module.

## The idea

A person who believes a zebra matures in about 900 days does not say "900". They say
"900", or "1000", or "2 years". The cognitive model predicts a **latent quantity**; the
person reports it on a **coarse grid**. Modelling only the first half and comparing against
a model that captures both is not a fair comparison.

So we add a reporting stage. With granularities
$g \in \{1, 5, 10, 50, 100, 500, 1000\}$ and mixing weights $\pi_g$:

$$
P(y) = \sum_g \pi_g \cdot \mathbb{1}[y \equiv 0 \bmod g] \cdot P_g(y),
\qquad
P_g(y) = \frac{\Phi\!\left(\frac{y + g/2 - \mu}{\sigma}\right) - \Phi\!\left(\frac{y - g/2 - \mu}{\sigma}\right)}{Z_g}
$$

Read it as: *with probability $\pi_g$ the person reports to the nearest multiple of $g$;
given that, the chance they land on $y$ is the latent distribution's mass in the bin around
$y$.*

Grid-$g$ bins tile $[-g/2,\; N_g g + g/2]$ exactly, so $Z_g$ is closed form and each $P_g$
sums to one over its own support. With $\sum_g \pi_g = 1$ the mixture is a proper PMF —
directly comparable to Centaur's token probability.

::: {.callout-tip}
## Why $\pi_g$ is free
It is estimated from each participant's **training-phase** responses, so it costs **no free
parameters** in the test-phase fit. A person's rounding habit is measured before the data
we are modelling.
:::

## `fit_granularity_weights(train_responses, grids=GRIDS, alpha=1.0)`

```python
def coarsest_grid(y, grids=GRIDS, tol=1e-8):
    y = np.asarray(y, dtype=float)
    out = np.zeros(y.shape, dtype=int)
    for k, g in enumerate(grids):
        on = np.abs(y / g - np.round(y / g)) < tol
        out = np.where(on, k, out)
    return out
```

`y / g - round(y / g)` is zero exactly when `y` is a multiple of `g`; comparing to a small
tolerance rather than `== 0` avoids floating-point trouble. Because `grids` is ordered
coarsest-last and each iteration overwrites, `out` ends up holding the **coarsest** grid
each value lies on. `np.where(cond, a, b)` is R's `ifelse()`, elementwise.

```python
def fit_granularity_weights(train_responses, grids=GRIDS, alpha=1.0):
    y = np.asarray(train_responses, dtype=float)
    y = y[np.isfinite(y)]
    counts = np.full(len(grids), float(alpha))
    if y.size:
        idx = coarsest_grid(y, grids)
        counts += np.bincount(idx, minlength=len(grids))
    return counts / counts.sum()
```

`np.bincount` tabulates counts of each integer — R's `tabulate()`. `minlength` guarantees
all seven slots exist even if some grid never occurs. Starting `counts` at `alpha = 1`
is **Laplace smoothing**: no grid ever gets probability zero, which matters because a zero
would make any test response on that grid infinitely surprising.

Observed averages for Mammals:

```

pi      [0.308 0.070 0.198 0.122 0.188 0.048 0.067]
```

## `_log_ndtr_diff(a, b)` — numerically stable $\log(\Phi(b) - \Phi(a))$

Computing $\Phi(b) - \Phi(a)$ naively then taking the log underflows to $-\infty$ in the
tails — and the optimiser spends a lot of time in the tails.

```python
def _log_ndtr_diff(a, b):
    a, b = np.asarray(a, dtype=float), np.asarray(b, dtype=float)
    lo, hi = np.minimum(a, b), np.maximum(a, b)

    use_upper = (lo + hi) > 0.0
    x_big  = np.where(use_upper, -lo, hi)
    x_smll = np.where(use_upper, -hi, lo)

    log_big  = log_ndtr(x_big)
    log_smll = log_ndtr(x_smll)
    ratio    = np.clip(log_smll - log_big, None, -1e-12)
    return log_big + np.log1p(-np.exp(ratio))
```

`log_ndtr` from `scipy.special` computes $\log \Phi(x)$ accurately even at $x = -40$.

The algebra: factor out the larger term,
$$\log(\Phi(b) - \Phi(a)) = \log \Phi(b) + \log\!\left(1 - \tfrac{\Phi(a)}{\Phi(b)}\right)$$
and compute the ratio in log space. `np.log1p(x)` is $\log(1+x)$, accurate for tiny `x`.

The `use_upper` switch handles the right tail. When both bounds are far positive,
$\Phi(a)$ and $\Phi(b)$ are both ≈ 1 and their ratio ≈ 1, so `log1p(-1)` → $-\infty$
catastrophically. By symmetry $\Phi(b) - \Phi(a) = \Phi(-a) - \Phi(-b)$, so we flip signs
and work in the left tail where `log_ndtr` is accurate. `(lo + hi) > 0` tests the midpoint.

`np.clip(x, None, -1e-12)` caps the ratio just below zero (`None` = no lower bound),
guarding against `log1p(0)` when rounding makes the two identical.

## `grid_masks(y, ...)` — precompute what the optimiser would recompute

```python
def grid_masks(y, grids=GRIDS, tol=1e-8):
    y = np.asarray(y, dtype=float)
    m = np.stack([np.abs(y / g - np.round(y / g)) < tol for g in grids])
    m[0] |= ~m.any(axis=0)
    return m
```

Which responses lie on which grid depends only on the **data**, never on the parameters. So
it is computed once per participant and reused across every objective evaluation — worth
roughly a 2× speedup, because the optimiser calls the likelihood thousands of times.

`m[0] |= ~m.any(axis=0)` is a safety net: `|=` is in-place OR, so any response on *no* grid
(a non-integer estimate) is forced onto the finest grid. Without it such a response would
have zero support and produce `NaN`.

## `logpmf_reported(...)` — the PMF itself

```python
    g   = np.asarray(grids, dtype=float)[:, None]        # (G, 1)
    loc = loc[None, :]                                   # (1, n)

    half = g / 2.0
    log_bin = _log_ndtr_diff(
        (edge(np.maximum(y[None, :] - half, lo_support)) - loc) / sigma,
        (edge(y[None, :] + half) - loc) / sigma,
    )
    log_z = _log_ndtr_diff(
        (edge(np.maximum(-half, lo_support)) - loc) / sigma,
        (edge(np.floor(ub / g) * g + half) - loc) / sigma,
    )

    comps = np.where(masks, log_pi[:, None] + log_bin - log_z, -np.inf)

    top = comps.max(axis=0)
    return top + np.log(np.exp(comps - top[None, :]).sum(axis=0))
```

This is broadcasting doing real work. `g` is `(7, 1)`, `loc` is `(1, n)`, so `g - loc`
broadcasts to `(7, n)` — every grid against every trial, in one array. Both
`_log_ndtr_diff` calls therefore happen **once** rather than once per grid.

::: {.callout-note}
## Why that matters
The original loop-over-grids version made 14 small calls per objective evaluation. At 1744
evaluations per participant fit, the per-call Python overhead dominated. Vectorising took a
single-participant fit from 3.0 s to 1.4 s with identical results.
:::

- `edge` is a *lambda* (an anonymous function, R's `\(x)`) that is the identity for
  `dist="normal"` and `np.log` for `dist="lognormal"`. Defining it once keeps the two
  distributions on one code path.
- `np.floor(ub / g) * g` is the largest multiple of `g` at or below the ceiling — the top
  of grid `g`'s support.
- `np.where(masks, ..., -np.inf)` zeroes out (in log space) every grid a response does not
  lie on.
- The last two lines are `logsumexp` written out: subtract the max, exponentiate, sum, take
  the log, add the max back. Doing it inline rather than calling `scipy.special.logsumexp`
  removed measurable overhead.

## `predict` and `nll_reported`

```python
def predict(model_fn, theta, cues, ex_cues, ex_crit):

        pred = model_fn(np.asarray(theta, dtype=float), cues, ex_cues, ex_crit)
    except Exception as exc:

    pred = np.asarray(pred, dtype=float)
    if pred.shape != (cues.shape[0],):
        raise ModelEvaluationError(...)
    if not np.all(np.isfinite(pred)):
        raise ModelEvaluationError("predictions contain NaN or inf")
    return pred
```

**This is the fix for v1's sentinel bug.** Any failure — an exception, a wrong shape, a
`NaN` — becomes a raised `ModelEvaluationError`. It never returns a number that could be
mistaken for a fit. `raise ... from exc` preserves the original traceback.

```python
def nll_reported(theta, model_fn, y, cues, ex_cues, ex_crit, pi, ub,
                 sigma_scale=1.0, dist="normal", agg="sum", mask=None, masks=None):
    theta = np.asarray(theta, dtype=float)
    sigma = float(sigma_scale) * float(softplus(theta[-1])) + SIGMA_MIN
    pred  = predict(model_fn, theta[:-1], cues, ex_cues, ex_crit)
```

`theta[:-1]` is everything but the last element; `theta[-1]` is the last (negative indexing
counts from the end). The last parameter is the **hidden noise parameter** the LLM never
sees.

`softplus(x) = log(1 + exp(x))` maps any real to a positive number smoothly. Multiplying by
`sigma_scale` — set to that participant's response SD — means `theta[-1] ≈ 0` already gives
a sensible sigma, keeping BFGS well conditioned. v1 started sigma at `0.01`, which on the
raw scale is an absurdly sharp distribution and a terrible starting point.

# `asmr_models_seed.py` — the model contract {#sec-models}

315 lines, mostly strings. The models live as **source code strings** because they are sent
to the LLM as text and executed by the harness.

## The contract

```python
NUM_PARAMETERS = <int>

def model(parameters, cues, ex_cues=None, ex_crit=None) -> pred_crit
```

Three rules, all changed from v1:

1. **Return only `pred_crit`** — a 1-D array. Not `(pred_crit, sigma)`. In v1 the LLM kept
   drifting between the two conventions; 8 of the 10 sentinel-producing generations did
   exactly that.
2. **Parameters are unconstrained reals of order 1.** Constraints go *inside* the function
   (`np.exp` for positive, sigmoid for $[0,1]$, softmax for a simplex). **There is no
   `BOUNDS` variable.** v1's LLM-authored bounds routinely went stale — one model returned
   `np.exp(...)` while paired with `BOUNDS = [(-4, 4)] * 11`.
3. **Predictions on the raw criterion scale**, with the scale set from `ex_crit` /
   `ex_cues` statistics so that `parameters = 0` already predicts plausible magnitudes.

## The GCM, annotated

`d_ref` is the median pairwise distance among exemplars — a natural distance unit for this
stimulus space. Dividing by it means `parameters[0] = 0` gives a sensitivity of
`1 / d_ref`, i.e. "similarity falls off over about one typical exemplar spacing".
`np.clip(..., -20, 20)` stops `np.exp` overflowing when the optimiser wanders.

`axis=-1` means "the last axis" — here the cue dimension.

Attention weights, non-negative and summing to `n_dim` as the manuscript requires. The
first logit is **pinned at zero** and only `n_dim - 1` are free — because softmax is
invariant to adding a constant to all logits, so `n_dim` free logits would leave one
parameter unidentified.

:::

## The other seeds

- **CAM** (11 parameters) — linear. `intercept = mean(ex_crit) + parameters[0] *
  std(ex_crit)`, weights scaled by `std(ex_crit) / std(ex_cues)` so all parameters are
  order 1.
- **RulEx-J** (22) — `alpha * CAM + (1 - alpha) * GCM`, with `alpha` through a sigmoid.
  Manuscript Eq. 5.
- **MAPP** (3) — the Mapping model. Cues are recoded to correlate positively with the
  criterion, averaged to a single value, then mapped to a typical criterion value.
  Implemented as a **kernel (Nadaraya–Watson) regression**: the bin width becomes a
  bandwidth. This keeps it differentiable for gradient-based fitting, at the cost of soft
  rather than hard bins.
- **Constant** (1) — same prediction on every trial. Uses **no information about the
  item**, so under the shared reporting layer it is the honest "response style only" null.
  Whatever a real model gains over this is what knowing the item buys.

## `Fit` — the result record

## `fit_one(...)` — one participant

::: {.callout-important}
## `OBJECTIVE_PENALTY` is not a sentinel
It looks like v1's `1e12`, but the difference is decisive. It is used **only inside the
objective**, to tell the optimiser "this region is bad, go elsewhere". The reported number
is recomputed afterwards:

```python

        raise ModelEvaluationError("no restart produced a usable fit")

```

So a fit that ends in a bad region is **discarded**, never reported.
:::


**BFGS, not L-BFGS-B**, because parameters are unconstrained by contract, so there are no

## Parallelism

Fitting is the slow part: BFGS with **numerical** gradients needs `k+1` extra evaluations
per gradient step (there is no analytic gradient for arbitrary LLM-written code). The 48
per-participant fits are independent, so they parallelise perfectly.

```python
_WORKER = {}

def _worker_init(source, cues, ex_cues, ex_crit):
    from asmr_codegen import validate_model_code
    np.seterr(over="ignore", invalid="ignore", divide="ignore")
    rep = validate_model_code(source, cues, ex_cues, ex_crit, n_draws=2)
    if not rep.ok:
        raise RuntimeError(rep.error)
    _WORKER["model_fn"] = rep.model_fn
```

::: {.callout-note}
## Why workers get *source*, not the function
Model functions come from `exec`, and **`exec`-created functions cannot be pickled** —
Python's multiprocessing serialises arguments to send them between processes, and it has no
way to reconstruct a function with no importable module. So each worker receives the source
text and rebuilds the function once, in its own `_worker_init`. `_WORKER` is a
module-level dict acting as per-process storage.
:::

```python
    if n_jobs and n_jobs > 1 and source is not None:
        import multiprocessing as mp
        with mp.Pool(n_jobs, initializer=_worker_init,
                     initargs=(source, ds.cues, ds.ex_cues, ds.ex_crit)) as pool:
            results = pool.map(_worker_fit, jobs)
    else:
        _WORKER["model_fn"] = model_fn
        results = [_worker_fit(j) for j in jobs]
```

`with ... as pool:` is a *context manager* — it guarantees the pool is closed even if an
exception occurs (R's `on.exit()`). The serial branch reuses the identical worker function,
so both paths are guaranteed to compute the same thing.

Measured on the A100 node: `n_jobs=8` takes a GCM fit over all 48 participants from several
minutes to about 34 seconds.

## `crossval_ll(...)` — the honest criterion

```python
def crossval_ll(model_fn, k, ds, pis=None, dist="normal", n_folds=5, n_restarts=3,
                seed=0, split_seed=0, n_jobs=1, source=None):
    pis = granularity_weights(ds) if pis is None else pis
    order = np.random.default_rng(split_seed).permutation(ds.n_items)
    folds = np.array_split(order, n_folds)
```

The 68 test items are split into folds; the model is fitted on the rest and scored on the
held-out fold.

::: {.callout-important}
## `split_seed` must be held constant
This is subtle and it matters. `seed` varies the optimiser restarts; `split_seed` fixes the
**item folds**. Re-scoring the *same* model under different fold splits moves held-out LL by
hundreds of nats:

| | held-out LL, same model, 3 repeats | spread |
|---|---|---|
| fold split reseeded each time | −18631, −19041, −19204 | **573** |
| fold split fixed (`split_seed` constant) | −19108, −19129, −19162 | **55** |

A 10× reduction. Without this, "did the model improve?" is partly a comparison of fold
splits rather than of models. The pipeline passes `split_seed=run_id`, constant across a
run's iterations.
:::

**Why cross-validation and not just AIC:** the LLM chooses its own `NUM_PARAMETERS`. It can
lower AIC by proposing fewer parameters and raise it by proposing more, independently of
whether the model is any good. Held-out likelihood cannot be gamed that way.

## `regret(fit, ds)`

## `format_covariates` and `residualize` — the key refinement

```python
def format_covariates(ds):
    y   = ds.estimates.T                                   # (n_subs, n_items)
    cov = [np.ones_like(y),
           (y % 100 == 0).astype(float),
           (y % 10 == 0).astype(float)]

    reused = np.zeros_like(y, dtype=float)
    for p in range(ds.n_subs):
        v, c = np.unique(ds.estimates[ds.valid[:, p], p], return_counts=True)
        dup  = set(v[c > 1])
        reused[p] = [e in dup for e in ds.estimates[:, p]]
    cov.append(reused)
    return np.stack(cov, axis=-1)
```

Four regressors describing **how the participant wrote the number down**: an intercept,
multiple-of-100, multiple-of-10, and whether they used that value more than once.

`np.unique(..., return_counts=True)` returns values and counts (R's `table()`); `c > 1`
finds the repeated ones. Membership testing uses a `set` because `in` on a set is constant
time.

```python
def residualize(delta, ds):
    cov = format_covariates(ds)
    out = np.full_like(delta, np.nan)
    for p in range(delta.shape[0]):
        m = np.isfinite(delta[p])
        if m.sum() <= cov.shape[-1]:
            out[p, m] = delta[p, m]
            continue
        X, d = cov[p][m], delta[p][m]
        beta, *_ = np.linalg.lstsq(X, d, rcond=None)
        out[p, m] = d - X @ beta
    return out
```

An ordinary least-squares regression of $\Delta$ on the format covariates, **within each
participant**, keeping the residual. `np.linalg.lstsq` is `lm()`; `beta, *_ = ...` unpacks
the first return value and discards the rest (`*_` swallows any number of extras). `@` is
matrix multiplication.

::: {.callout-tip}
## What this buys
| corr($\Delta$, …) | v1-style | v2 + residualised |
|---|---|---|
| response is a multiple of 100 | +0.47 | 0.00 |
| participant reused this value | +0.47 | 0.00 |

And on what actually matters — the trials that get selected:

| selection rule | median \|log residual\| of selected trials |
|---|---|
| all trials (baseline) | 0.365 |
| plain $\Delta$ | 0.682 |
| residualised $\Delta$ | **0.861** |

The LLM now sees trials where the model is 2.4× further off than typical, instead of 1.9×.
:::

`np.argsort(-x)` sorts **descending** (numpy has no `decreasing=` flag; negating is the

**`diagnostic_block`** — aggregate residual structure. This is arguably the most valuable

```
* mean residual over all items: +130.2
* correlation of the residual with the distance to the nearest exemplar: +0.18
* correlation of the residual with the true criterion value: +0.33
* correlation of the residual with the model's own prediction: +0.24
* mean residual for the lowest-predicted third  (model predicts  323): +64.1

* mean residual for the highest-predicted third (model predicts 1642): +239.1
```

Those last three lines are a textbook signature: the GCM **compresses the range**, because

# `asmr_evaluate.py` — individual differences without overfitting {#sec-evaluate}

253 lines.

## The design

You raised the right concern: fitting one shared model form to everyone may hide real
strategy differences. But discovering a **bespoke model per person** overfits badly — with
68 trials the LLM will happily tailor a model to one person's quirks.

The resolution is **model selection over a library**:

1. Run ASMR several times with different seeds and starting models.
2. Every *validated* model along the way goes into `library.jsonl`.
3. Score every library member against every participant on **held-out items**.
4. Assign each participant their best-scoring member.

Individual differences then show up as *which model wins for whom* — the same logic as your
manuscript's posterior model probabilities, and directly comparable to Table 2.

## `per_participant_heldout(...)` and `evaluate_library(...)`

`seed` fixes the folds and is identical for every library member, so the comparison is
**paired** — the same items are held out for every model.

```python

              .rename("n_participants").reset_index())
```

`groupby(...)["col"].idxmax()` gives the row *index* of the maximum within each group;
`.loc[...]` then pulls those rows. This is `dplyr::slice_max(heldout_ll, by = participant)`.

is not what these data want once granularity is modelled.

## Cost

Per `fit_all` over 48 participants with `n_jobs=8`: roughly 10 s (Constant) to 120 s
(RulEx-J). `crossval_ll` multiplies that by `n_folds`. A five-iteration chain with
five-fold CV is on the order of 20–40 minutes plus generation time.

# Extending it {#sec-extending}

## A new domain

`Food` and `Countries` already work. You need:

1. An entry in `DOMAIN_CONFIG` (already present for all three).
2. An aligned Centaur file, `log_likelihood_<Domain>_TESTING_ALIGNED.pth`.
3. An entry in `asmr_srm.DOMAIN_TEXT` (all three present) giving `criterion`, `unit` and
   `objects` — the phrases that go into the prompt.

```python
ds = load_aligned("Food")     # 14 cue dimensions, ub = 100
```

The seeds read `n_dim` from `cues.shape[1]`, so CAM and RulEx-J need their
`NUM_PARAMETERS` adjusted for a 14-dimensional domain (CAM: `1 + 14 = 15`).

::: {.callout-warning}
`GRIDS` is tuned for Mammals, where the criterion runs to 10000. For Food and Countries
(ceiling 100) the coarse grids 500 and 1000 lie outside the support and just absorb
smoothing mass. Consider `GRIDS = (1, 5, 10, 25, 50)` for those domains.
:::

## A new seed model

Write it as a string following the contract, add it to `SEED_MODELS`, and validate:

```python
MODEL_MINE = PREAMBLE + '''
NUM_PARAMETERS = 2

def model(parameters, cues, ex_cues=None, ex_crit=None):
    """Compute predicted criterion estimate."""
    mu    = np.mean(ex_crit)
    scale = np.std(ex_crit)
    d     = np.linalg.norm(cues[:, None, :] - ex_cues[None, :, :], axis=-1)
    near  = d.min(axis=1)
    return mu + parameters[0] * scale + parameters[1] * scale * near
'''

SEED_MODELS["Nearest"] = MODEL_MINE
```

```python
from asmr_codegen import validate_model_code
rep = validate_model_code(MODEL_MINE, ds.cues, ds.ex_cues, ds.ex_crit)
print(rep.ok, rep.num_parameters, rep.error)
```

Always validate before running — it catches the shape, dead-parameter and finiteness
mistakes in seconds.

## The response-perseveration extension

The largest remaining gap. Centaur is **autoregressive over the participant's own answer
history**, so it exploits the fact that 46% of test responses repeat a value that person
already gave. A cognitive model predicting one quantity per item structurally cannot.

Residual evidence: after residualising, corr($\Delta$, reused) is driven to 0 by
construction, but before residualising it is +0.21 — that is real, unmodelled structure.

`ds.pres_pos` preserves the presentation order needed to build this. A model would need
access to the responses given *before* the current trial, which means extending the model
contract beyond `(parameters, cues, ex_cues, ex_crit)`. That is a deliberate scope
increase, not a small edit — but it is the obvious next scientific step, and arguably a
finding in its own right.

## A different response distribution

`logpmf_reported` already switches on `dist`. Adding a third would mean defining `loc`,
`edge` and `lo_support` for it in that function. The `_check_pmf_sums_to_one` self-test
should be run for any new one.

# Troubleshooting {#sec-trouble}

**`FileNotFoundError: '../Data/...'`**
: Not running from `Scripts/`. All paths are relative.

**`NameError: name 'make_generator' is not defined`**
: Notebook cells run out of order. Section 1's import cell has not executed. The
  model-loading cell now imports it itself, but sections 5–7 still need `ds`, `pis` and
  `N_JOBS` from sections 1–2.

**`AssertionError: ALIGNMENT BROKEN for participant ...`**
: The guard is doing its job. Either `narrative_data.csv` was regenerated without
  re-running `extract_nll_testing_phase_only.py`, or the behavioural file changed. Do not
  disable the check — the whole point is that this failure is silent otherwise.

**`AssertionError: Centaur NLL shape (...) != (...)`**
: Stale `_TESTING_ALIGNED.pth`. Re-run `extract_nll_testing_phase_only.py` with the right
  `DOMAIN` (note that script has a hardcoded `DOMAIN = "Food"` at the top).

**`RuntimeError: the seed model itself failed validation`**
: A bug in `asmr_models_seed.py`, not in the LLM output. Run `python asmr_codegen.py` for
  the specific error.

**`ModelEvaluationError: no restart produced a usable fit`**
: Every restart landed in a region where the model is unevaluable. Usually a generated
  model with a genuine pathology; the loop rolls back. If a *seed* does this, check
  `sigma_scale` and whether predictions are on the raw scale.

**Held-out LL jumps by hundreds of nats between iterations of the same model**
: `split_seed` is varying. It must be constant within a run.

**`nats_per_trial` near 7.6 instead of 5.5**
: The reporting layer is not active — check that `pis` is being passed and that
  `ds.train_est` is non-empty for your participants.

**Parallel fitting hangs or errors**
: Set `n_jobs=1` to confirm it is the parallelism. Remember `source=` must be passed
  alongside `n_jobs>1`; without it `fit_all` silently falls back to serial.

**Overflow warnings from `<llm_model>`**
: Generated models exploring extreme parameters. Harmless — `np.seterr(over="ignore")` is
  set in workers. The seeds clip their exponents to `[-20, 20]` for this reason.
